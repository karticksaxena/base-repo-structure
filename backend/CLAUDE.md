# Backend Coding Rules

## Dev tooling

Follow **`../SETUP.md`**. Lint, type, size and test rules live in `pyproject.toml`; layer rules in `tach.toml` (app level) and each feature's `tach.domain.toml` — never in `.vscode/settings.json`, and never in a separate `pyrightconfig.json`, `.flake8` or `.pylintrc`.

## Stack

FastAPI · Pydantic + pydantic-settings · **dishka** (DI) · **loguru** (logging) · pytest · `uv` (package manager, never pip) · Python from `.python-version`

Added only when a feature needs them (`../SETUP.md` → Libraries by use case): **SQLAlchemy** (async ORM) + asyncpg · Alembic (migrations) · redis · httpx2 (outgoing HTTP)

Always the latest stable, mutually compatible versions — never prereleases, never versions hardcoded in docs.

## NestJS-style structure (enforced — the linters fail on violations)

```
src/app/
  main.py                 # app factory: logger, routers, dishka (Nest main.ts)
  app_module.py           # root module (Nest AppModule): dishka container with every feature's Provider
  core/                   # app-wide setup: config, logger (+ database, redis) — never imports a feature
  common/                 # shared by 2+ features: schemas.py (BaseSchema, Page[T]), base repositories, domain errors (NestJS common/)
  features/<name>/        # one NestJS module per domain
    __init__.py
    routers/              # HTTP only (Nest controllers); __init__.py combines them into one `router`
    services/             # business logic (Nest services)
    repositories/         # data access — the only layer that touches the database or Redis
    schemas/              # Pydantic request/response models (Nest DTOs)
    constants/            # fixed values used only by this feature (limits, mappings, enums)
    utils/                # small helpers used only by this feature (formatting, transforming) — no business logic
    models/               # SQLAlchemy models (Nest entities) — once a database exists
    dependencies.py       # dishka Provider (Nest module providers)
    tach.domain.toml      # this feature's layer rules — identical in every feature
```

Every layer folder is a package (`__init__.py`) holding one module per use-case area (`services/items.py`, `services/item_exports.py`).

### Where code goes

- HTTP (paths, status codes, request parsing) → `routers/`; business rules → `services/`; database, Redis or other data sources → `repositories/`
- Request/response shapes → `schemas/`; fixed values and enums → `constants/`; small pure helpers → `utils/`
- Used by one feature → stays in that feature; needed by a second feature → move it to `common/`; app-wide setup → `core/` — never import another feature's internals

### Adding a feature (`orders`)

1. `cp -R src/app/features/items src/app/features/orders` — every folder, `__init__.py` and `tach.domain.toml` comes along; never edit the copied `tach.domain.toml`
2. Rename the modules in each layer folder (`routers/items.py` → `routers/orders.py`, …), the classes (`ItemService` → `OrderService`, …) and **every import** (tach rejects any import still pointing at `items`); keep every folder, even an empty `constants/` or `utils/`
3. Point `routers/__init__.py` at the new router module; register the router in `main.py` and the provider in `app_module.py`
4. Add `tests/features/orders/test_*.py`
5. Run every check (`../SETUP.md` → Verify CLI) — done only when all pass

### Changing the layer rules (ask first)

Edit `features/items/tach.domain.toml`, then copy it to every feature: `find src/app/features -mindepth 1 -maxdepth 1 -type d ! -name items ! -name __pycache__ -exec cp src/app/features/items/tach.domain.toml {}/ \;`. A new kind of folder (e.g. `tasks/`, `listeners/`, `grpc/`) also goes into `REQUIRED_PACKAGES` in `tests/pylint_structure.py` and into every feature.

### When a check fails

- Change the code to fit the structure — never loosen `tach.toml`, a `tach.domain.toml`, a pylint plugin or a lint rule, never add `# tach-ignore` / `# noqa: TID…`, and **never run `tach sync`** (tach suggests it; it rewrites the rules to allow whatever the code imports)
- `lint-imports` names only the two features (`.orders -> .items (1 import)`); find the import with `grep -rn 'features\.items' src/app/features/orders` and break the loop: move what both need to `common/`, or let only one feature call the other. Never add `ignore_imports` to `[tool.importlinter]`
- `E9001 … built outside dependencies.py`: take the object as an `__init__` parameter and build it in the feature's `dependencies.py` Provider. `E9002 Depends(X) builds it outside dishka`: take `FromDishka[X]` instead. pylint loads the plugin from `tests/`, so it runs from `backend/` (the editor and every check already do)
- Trust `uv run tach check` over the editor after editing files: the Tach extension doesn't see disk changes until the file is reopened or **Tach: Restart Server** runs
- `E9003 Depends(x)`: take `FromDishka[X]` and provide `X` in the feature's Provider; for request parameters, group them in a `BaseSchema` and use bare `Depends()`
- `E9006 logic in a route`: move it to the service; a 404 is a domain error the service raises (rule 8), not an `if` in the route
- `E9010 path` on a word that is really singular (`/health`, `/people`, `/auth`): ask first, then add it to `SINGULAR_ALLOWED` in `tests/pylint_api.py`. `E9014` on a `POST` that creates nothing (login): ask first
- A layout error (`E9030`) shows on line 1 of every open file: it is about the folders, not that file
- The checks live in linters so the errors show while editing. Don't add test files that enforce rules; `tests/` holds behaviour tests. A rule a linter can't see goes in the list below
- Not caught by any tool (each one verified by a probe), so keep it by hand:
  - routers hold no business logic: `max(a, b)` or two service calls in a route pass `E9006`
  - services and repositories are built only in `dependencies.py`, however the call is written: `partial(ItemRepository)()`, a class passed as a parameter (`make(ItemRepository)`) and `ItemRepository.__new__(ItemRepository)` slip past `E9001`
  - the right provider scope: a slow class on `Scope.REQUEST` passes (it costs its build time on every request)
  - which layer code belongs in when the imports are allowed; services raising domain errors rather than `ValueError` (rule 8); route permissions, since auth isn't built yet
  - word lists: `E9010`, `E9012` and `E9015` read names, so a secret called `token`, a verb they don't list or business data in a header passes; `PUT` replacing a whole record is unchecked
  - logging in loops or on plain reads (rule 7); the performance defaults in rule 12
  - the rules themselves: editing `tach.toml`, `pyproject.toml`, a plugin, `features/items/tach.domain.toml` (the template, while `items` is the only feature) or running `tach sync` passes. Code review catches it
  - the editor lints open files only and one at a time: duplicate route names across files (`E9013`) show only on a full run (`check: all`, CLI, pre-commit hook)
  - `tests/pylint_api.py` works out where FastAPI reads each parameter from by reading the source; after a FastAPI upgrade that changes those rules, re-check `parameter_source`

## Rules

A rule is enforced only where a tool is named next to it; everything else here is kept by hand.

1. **NESTJS-STYLE STRUCTURE** — see the section above
2. **REPOSITORY PATTERN** — all DB/Redis access goes through `repositories/`; no queries in services. Once a database exists (`../SETUP.md` → Database pattern): models in `models/`, inheriting `Base` (UUIDv7 `id`, UTC timestamps, soft delete — never redeclare them); every database repository inherits `RepositoryBase` (`common/repository.py`) and adds only its own queries, starting from `base_statement()` (hides soft-deleted rows); delete with `soft_delete()`; repositories flush, never commit — the session provider in `core/database.py` commits on success and rolls back on error; no unbounded queries (`paginate` + `count`); services return Pydantic schemas, never ORM objects. Once Redis exists (`../SETUP.md` → Redis pattern): one app-wide client from `core/redis.py`; cached reads go through a `Cached<X>Repository` (inherits `CachedRepositoryBase`, `common/cached_repository.py`) — cache-aside, and the service **invalidates after every write**; other Redis use inherits `RedisRepositoryBase` (`common/redis_repository.py`); keys always via `self.key(...)` with a TTL
3. **DI THROUGH DISHKA** — register each feature's `Provider` in `app_module.py` (the root module, like Nest's `AppModule`); routers use `route_class=DishkaRoute` (pylint `E9017`) and take `FromDishka[Service]`; request-scoped objects (DB session, current user) come from providers, never built in a route. FastAPI `Depends` only as bare `Depends()` to group request parameters (headers, query) — `Depends(anything)` is pylint `E9002` / `E9003`; pagination uses `Limit` / `Offset` from `common/schemas.py`
4. **ABSOLUTE IMPORTS** — `from src.app.X import Y`; relative imports only in `__init__.py`
5. **RETURN TYPES FIRST** — every route declares its return type, a schema, `Page[T]` or `None` (pylint `E9011`): FastAPI validates the result and Pydantic serializes it to JSON in Rust (about 1.5x faster than `JSONResponse` and 5x faster than declaring nothing, measured in-process on 20 items; a return type and `response_model=` run at the same speed). `response_model=` only when the route returns a different type than the public schema (`-> InternalItem` with `response_model=ItemResponse`); never repeating the return type (pylint `E9005`; Ruff `FAST001` doesn't fire on Python 3.14+, [ruff#20747](https://github.com/astral-sh/ruff/issues/20747)), never with `-> Any` (Ruff `ANN401`). To hide fields, returning a subclass of the public schema filters them with no `response_model=`. A dict with an extra key under a `BaseSchema` model is a 500, not a filtered response: return schema instances. For a JSON body return the schema — never `JSONResponse` or `jsonable_encoder` (Ruff `TID251`) or `response_class=` (each skips that path); `ORJSONResponse` / `UJSONResponse` are deprecated; `Response` subclasses only for non-JSON (files, redirects, streams). JSON requests need `Content-Type: application/json` (FastAPI's default `strict_content_type` — keep it on)
6. **SCHEMAS (Pydantic v2 API only)** — every schema inherits `BaseSchema` (`common/schemas.py`: unknown fields rejected, strings trimmed; Ruff `TID251`, pylint `E9021`). Trimming changes every string, so a field where spaces matter (a password) declares `Annotated[str, StringConstraints(strip_whitespace=False)]`; config via `model_config: ClassVar[ConfigDict]`; `model_validate()` / `model_dump()`, and `model_validate(obj, from_attributes=True)` for ORM objects — never `class Config`, `.dict()`, `.parse_obj()`, `orm_mode` or `pydantic.v1` (FastAPI dropped Pydantic v1; BasedPyright and pytest fail on the deprecated API); every field has `Field(description=...)` for the OpenAPI docs (pylint `E9004`, `E9020`); every list endpoint takes `limit: Limit = 20, offset: Offset = 0` and returns `Page[T]` (pylint `E9011`, `E9016`)
7. **LOGGING** — `from src.app.core.logger import logger` (Ruff bans importing `loguru` elsewhere); `{}` placeholders only (loguru doesn't support `%`: `logger.info("x %s", v)` writes a literal `%s`), never f-strings (Ruff `G004`, `G002`, pylint `E9007`): `{}` skips the formatting work when the level is off, and an f-string with braces in the data plus a keyword argument raises `KeyError`; `logger.exception()` inside `except`. Log external calls, DB writes, exceptions and state changes — never loops or plain reads
8. **ERRORS** — services raise domain exceptions, never `HTTPException` (`tach check-external`); when the first domain exception is added, register one exception handler in `main.py` that maps them to HTTP status codes and returns `Response(content=error.model_dump_json(), status_code=..., media_type="application/json")` (`JSONResponse` is banned)
9. **SECRETS** — only through `Settings` (`SecretStr`, pylint `E9022`); never hard-coded, logged or committed (`.env` is git-ignored)
10. **UTC** — store and compare datetimes in UTC; convert to the user's timezone only for display
11. **NO `api/` FOLDER** — feature routers are registered directly in `main.py`
12. **PERFORMANCE — RESEARCH FIRST** — before choosing a library, pattern or setting, use the **`grounded-research`** skill to find the fastest production-proven option for the installed versions (never from memory); measure before and after optimizing. Defaults:
    - `async def` routes await only async I/O — a blocking library goes in a `def` route (FastAPI runs it in a threadpool) or is replaced by an async one; CPU-heavy work goes to a background job or more workers, never into the request
    - Raw JSON → `Model.model_validate_json(raw)` (not `json.loads` + `model_validate`); a `TypeAdapter` is built once at module level; tagged (discriminated) unions over plain unions
    - Database: `lazy="raise"` on relationships + `selectinload()` (no N+1); bulk inserts as one list; select only the columns a large list needs; paginate everything
    - One client/pool per external service for the whole app (dishka `Scope.APP`); `Scope.REQUEST` only for per-request state; Redis `pipeline()` for batches
    - Production: `--workers` = CPU cores on Granian (default) or uvicorn (one worker per container under an orchestrator); stay on the GIL build of Python and off the experimental JIT until their support is production-ready
    - Speed comes from Pydantic's Rust core, Granian, asyncpg and query design — dishka and SQLAlchemy are chosen for structure, not speed
13. **HTTP API DESIGN** — the URL names the record; the body carries the change (pylint `E9010`–`E9019`, `tests/pylint_api.py`):
    - Path: plural nouns and ids only (`/orders/{order_id}`), no verbs
    - Query: filters, sorting, `limit` / `offset` — on `GET` only
    - Body: create/update data as a schema; none on `GET` or `DELETE`
    - Headers: auth and request metadata (`Idempotency-Key`), never business data
    - Methods: `GET` reads · `POST /orders` creates (201) · `PATCH /orders/{order_id}` updates the fields sent · `DELETE /orders/{order_id}` deletes (204); `PUT` only to replace a whole record
    - Never secrets or personal data in the path or query — servers, proxies and browsers log URLs (RFC 9110 §17.9)
    - The acting user comes from auth (a dishka provider), never from a header the client sets
    - A `POST` that must be safe to retry (payments) takes an `Idempotency-Key`; add it only when an endpoint needs it
    - Route function names are `<verb>_<noun>` (`list_items`, `create_order`) and unique across the app (pylint `E9012`, `E9013`) — once Hey API is added they become the OpenAPI operation ids and the frontend's function names (`listItems`)
    - Routes are added with a decorator and a literal path; `prefix=` goes on the `APIRouter`, never in `include_router()` (pylint `E9018`, `E9019`): the linter reads the source, so anything else would hide from it

## Tests

- `tests/` mirrors `src/app/features/` — every feature has `tests/features/<name>/test_*.py` (pylint `E9030`)
- `@pytest.mark.unit` (no DB) or `@pytest.mark.integration` (real DB/Redis, rolled back after each test), pylint `E9023` — never mock the DB in integration tests
- Never call external APIs or LLMs in tests — mock them: unit-test a service by passing fakes to its `__init__`; in a router test replace the provider with `TestClient(create_app(FakeProvider()))` (a later provider wins — `SeededItems` in `tests/features/items/test_router.py`)
